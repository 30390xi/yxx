# 本地接口后台技术说明

## 目标

用可检查、可编辑的实测响应支撑小程序页面复刻和接口联调。当前实现覆盖已触发的 46 条公开浏览接口，包括首页、景区、门票商品、攻略及线路商品列表与详情。

## 组成

- `src/FixtureServer.java`：JDK 8 内置 `HttpServer`，按 HTTP 方法、路径和排序后的查询参数定位样本。
- `fixtures/index.tsv`：服务端路由索引；`index.json`：管理页元数据。
- `fixtures/*.json`：接口响应体，保存后立即生效。
- `ingest_devtools_har.py`：从开发者工具 HAR 导入公开样本和已加载图片；有内嵌图片正文时直接保存字节，否则记录图片 URL 供缓存，并在提取后删除原始 HAR。
- `capture_public_images.py`、`build_image_map.py`、`localize_static_assets.py`：缓存公开图片，生成运行时映射并本地化 WXML 中实际观察到的图片引用。WXSS 中已缓存的小背景图内联为 data URI，以兼容开发者工具的样式加载限制。
- `build_client_routes.py`：生成小程序端精确匹配的 GET 路由白名单。
- `admin.html`：本机管理页，可搜索、查看、校验并保存 JSON。
- `extract_public_fixtures.py`：从 HAR 中筛选 `/base/app/` 和 `/product/app/` 的 JSON 成功响应；不会存储原始请求数据。

## 请求流程

1. 客户端对方法、路径和查询参数与抓包记录完全一致的公开 GET 请求使用本地 `127.0.0.1:8787`。路径内参数与请求对象参数统一拼入本地 URL；调用 `wx.request` 时不再重复传入数据对象，避免查询参数重复。本地请求失败或返回非 200 时恢复原 URL 与数据对象并回退到原接口；其他请求直接走原接口。
2. 服务端对查询参数排序并匹配路由索引。
3. 命中时从磁盘读取当前 JSON 文件并返回；未命中时返回明确的 404 错误体。
4. 管理页更新样本时先使用 JDK 8 的 JSON 解析器校验，再写入对应文件。

## 范围与后续

公开读取接口可以驱动已抓取的页面内容。登录、订单创建、支付、退款等写操作需要在有授权的测试账户和明确返回证据下另行实现，并采用真实状态模型与数据库；当前后台不会对这些操作返回虚假成功。8 条 POST 样本按路径匹配，尚未区分请求体，因此小程序端仅将 38 条精确匹配的 GET 样本路由到本地。图片样本保留原 URL，小程序运行时使用 566 张本地图片的映射。本地服务绑定 `127.0.0.1`，不应直接作为线上服务部署。

## 验证

使用 Amazon Corretto JDK 8 编译和启动。对全部当前样本路由请求并验证外层响应结构；验证管理页与索引可读取、合法 JSON 可保存、错误 JSON 被拒绝且原文件不变。小程序已在微信开发者工具 Stable 2.02.2608060 编译，并逐页观察首页、景区、门票、攻略及线路商品的公开浏览页面。线路地图使用抓包中的路线节点呈现；原地图密钥与新 AppID 不匹配。
